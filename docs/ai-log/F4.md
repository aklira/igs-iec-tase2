- **Gate**: the repository's gate (`bench/` is outside the workspace; `bench/peer/harness` is a separate crate).

## Found on the way

- The first build of the harness failed on the bookworm image of Rust 1.85: rusty-acse uses let-chains, which need Rust
  1.88 or later. The peer is built with Rust 1.90 (the bench is not part of the project's MSRV).
- rusty-iccp documents 0 % of its API (docs.rs): the scenario uses the signatures of the MMS service crate, which the
  README of the repository and the public signatures make clear enough. The ICCP client is not yet exercised: it is for
  the TASE.2 scenarios (T3).
- The device binary of the MMS repository cannot be built for musl here (the TLS of its X1 task needs a musl C compiler),
  so the device is built in the bookworm image, which the bench uses anyway.
