# B4 — Transfer sets

## Prompt

Run task B4 of `IMPLEMENTATION.md`: the state machine of the transfer sets: start, stop, conditions, interval, integrity,
change reports, critical acknowledgement, all with a fake clock. Read IEC 60870-6-503 §6.9 to §6.14, §7. Done when there is a
deterministic test per condition and per expiry.

## Summary

- **State machine**: `crates/igs-iec-tase2-link/src/transfer.rs`: `DataSetTransferSet`, started with its `Parameters` (the
  DSTransmissionPars of 503 §5.3.10.2.2 and the event code) and the `Policy` of the server. The inputs take the time: `advance`,
  `change`, `operator_request`, `other_event`, `stop`, `acknowledge`, `negative_acknowledge`. The outputs are the `Report`s
  (in time order), and the `Alert`s (the data failure).
- **Conditions**: IntervalTimeOut, IntegrityTimeOut, ObjectChange (with the buffer and All Changes Reported), OperatorRequest,
  OtherExternalEvent (with its event code); RBE and BlockData; Critical; TLE.
- **Decisions**: D-038 (timing), D-039 (report contents), D-040 (blocking), D-041 (critical), D-042 (TLE), D-043 (refusals at the
  start).
- **Tests**: `tests/transfer.rs`, 26 tests with a fake clock, each condition and each expiry, the contents, the blocking, the
  acknowledgement and the TLE, and the two refusals at the start.
- **Dependencies**: none new; the model's `DSConditions` and `Integer16`, and the codec's `Data`.
- **Gate**: `cargo fmt --all --check`, clippy with `-D warnings`, the workspace tests (189 passed), `cargo deny check` and
  `codegen --check`, all green.

## Found on the way

- Changes were kept for RBE only when the ObjectChange condition was requested. RBE interval reports need the changed members
  whatever the conditions (§5.3.10.2.2). The fix is in `change`; a test of the RBE interval without ObjectChange was the first
  to show it.
