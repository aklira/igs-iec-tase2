# T2 — `igstase2-client`: the command-line client

## Prompt

Run task T2 of `IMPLEMENTATION.md`: the `igstase2-client` binary, with its `--help` documented and a run recorded against the
bench device.

## Summary

- **Binary**: `crates/igstase2-client/` (`src/main.rs`). Global options (server, AP-title, domain, table identifier, timeout)
  and the commands `get`, `set`, `type`, `members`, `read`, `write`, `create`, `delete`, `start`, `stop`. Documented in
  `docs/igstase2-client.md`.
- **Exit status**: 0 when the operation was answered (per-item errors are printed, not counted), 1 for an association refused
  or concluded or a request refused, 2 for an invalid command line (D-056).
- **Bench run**: the device `device-tase2` of `bench/`, rebuilt after the server fix below, against which the commands were
  run. The transcript with the exit status of each command is `bench/transcripts/T2-run.txt`.
- **Fix made on the way**: a data set created by a client was invisible to it, so it could not read or delete it. The server
  now grants the creator the access (D-055), with a test.
- **Tests**: `crates/igstase2-client/tests/cli.rs` (4 tests, process-level, against an in-process server), and 3 unit tests of
  the value and AP-title parsing.
- **Gate**: the TASE.2 workspace: fmt, clippy with `-D warnings`, tests (240 passed), `cargo deny check`, and `codegen --check`,
  all green.

## Reading

IEC 60870-6-503 §7.2.2 (the association, its release), §7.2.3 (the data values), §7.2.4 (the data sets), §7.2.5 (the transfer
sets). No standard text is in the code or the documents.

## Not done / limits

- The client does not read a point's type before writing it: a value for an unsigned point is refused by the server (D-056).
- The bench peer of the plan (rusty-iccp) does not serve TASE.2 (D-010), so the run is against the device, which is the
  TASE.2 server of this repository, and not against a third-party peer.
