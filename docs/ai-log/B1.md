# B1 — Bilateral table

## Prompt

Run task B1 of `IMPLEMENTATION.md`: the bilateral table model, its access checks, and the `Bilateral_Table_ID` and version
checks, from IEC 60870-6-503 §5, §6.5 and §10. Done when there are tests for each access result.

## Summary

- **Table**: `crates/igs-iec-tase2-link/src/bilateral.rs`. A table per remote control centre (`BilateralTable`), holding the
  application references, and the data values, data sets, transfer sets and devices with their permitted operations; the
  intervals agreed; the CheckBackID and the Timeout of each device. `BilateralTables` holds the tables of a server and
  admits a client.
- **Checks**: `check` (visibility and the permitted operations), `check_interval` (the maximum exchange rate),
  `check_device_time` (the Timeout), `check_back_id` (returned for a selectable device), `admit` (designation and
  application reference). The results are in `Access` and `Admission` (D-027).
- **Versions**: `crates/igs-iec-tase2-link/src/version.rs`: `Versions`, `Tase2Version`, the version of this standard
  (2000.08), and `check_versions`, which compares the table identifier before the TASE.2 version (D-028).
- **Decisions**: D-027, D-028, D-029 (what is left to B2 and B5).
- **Tests**: `tests/bilateral.rs`, 22 tests: each access result, the scope of a name, the admission results, the version
  conflicts and their order, the replacement of a table, and the standard version.
- **Dependencies**: `igs-iec-tase2-link` depends on `igs-iec-tase2-model` (for `VisibleString32`), a path dependency
  (rule 9).
- **Gate**: `cargo fmt --all --check`, clippy with `-D warnings`, the workspace tests with all features, `cargo deny check`
  and `codegen --check`, all green.

## Found on the way

- The Permitted Access lists of the standard name the operations of each object type; the checks use the same names, so a
  test reads like the standard.
- The standard gives the version comparison as two steps of the association; the second happens only when the first
  passes (D-028).

## Reading

IEC 60870-6-503 §5.2.3 (the bilateral agreements and the access control of each object), §5.3.2 (the general access
control requirements), §5.3.3.3 (the Associate operation and the version checks), §5.3.4 (the Bilateral Table object model),
§5.3.5 (the access control specification), §6.5 (the mapping of the table), §8.3.3 and §8.3.4 (the variables of the
identifier and of the version), and the Permitted Access lists of §5.3.6.2, §5.3.7.2, §5.3.10.2.1 and §5.3.12.2. The clause 10 is the
semantic model (informative); it was not used for the checks. No standard text is in the code or the documents.
