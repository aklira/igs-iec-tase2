# S1 — Server

## Prompt

Run task S1 of `IMPLEMENTATION.md`: the `Server` with the bilateral tables, the objects through the VMD, and the transfer sets
reporting to each association. Done when there are integration tests per operation with the client.

## Summary

- **Server**: `crates/igs-iec-tase2/src/server.rs`: `TaseServer` (bind, local address, `set_value`, shutdown) and `TaseModel`,
  the model of the MMS server. It admits a client by its Bilateral Table (B2), answers the TASE.2 services per item under the
  table of the client (B1, B3), starts and stops the data set transfer sets per association (B4), and reports to the association
  that started them. The data values are the variables of the VMD of the MMS stack.
- **Sibling change**: the MMS server now serves a `Model` that names the association of each call, with admission, release and
  targeted outputs (D-031 of the MMS repository, on its branch `tase2-association-context`, committed locally and not pushed).
  The MMS initiator also sends its AP-title, which its configuration already held.
- **Decisions**: D-048 (designation and application reference), D-049 (the services served, and those not served), D-050 (the
  application's changes and their reports).
- **Tests**: `crates/igs-iec-tase2/tests/server.rs`, 15 tests through the client over TCP: the association, the special objects,
  the refused client, the table identifier conflict, the reads and writes per item, the data sets (read, written, created,
  deleted, unknown), the type of a value, the transfer reports (entire data set, by exception, after a stop), the refused
  change, and the transfer sets the server does not hold or whose data set is hidden.
- **Sibling tests**: `crates/igs-iso9506-mms/tests/server_model.rs` (4 tests) and the whole MMS suite (338 tests) pass on the branch.
- **Gate**: the TASE.2 workspace: `cargo fmt --all --check`, clippy with `-D warnings`, the tests (214 passed), `cargo deny check`
  and `codegen --check`, all green.

## Found on the way

- The MMS server accepted every Initiate before the model could look at it; the calling AP-title was decoded and discarded.
  The MMS change carries it to the model (D-031 of the MMS repository).
- The MMS initiator sent no AP-title even when its configuration held one.
- The client's association check needs the Bilateral Table of the server to name the variables by the spelling of D-045; the
  server answers them under that spelling.
- A change refused by the store was first reported, which made the report false; the change is now dropped when the store
  refuses it.

## Not done

- GetNameList, the blocked reports, the Data_failure event, and the acknowledgement of critical reports (D-049).
- The server's demonstration binary and its bench (S2), and the interop and load tests (S3).
- The branch of the MMS repository is not merged into `main` and not pushed: the CI of the TASE.2 repository checks out the
  sibling repository's `main`, so it does not see the change until the branch is merged.
