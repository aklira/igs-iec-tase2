# C5 — Extended data set conditions (block 2), end to end

## Prompt

Run task C5 of `IMPLEMENTATION.md`: check, in the client and the server, that a block-2 condition is requested and reported end to end, and
record what is not.

## Summary

- Block 2 is the ObjectChange and IntegrityTimeout conditions, and the transmission parameters they use: TLE, BufferTime, IntegrityCheck,
  Critical and RBE (D-060, Table A.7 of 702).
- Already covered before C5: ObjectChange with and without RBE, end to end (`a_change_of_a_monitored_value_is_reported_to_its_association`,
  `a_report_by_exception_carries_the_changed_member_only`).
- Added in `crates/igs-iec-tase2/tests/server.rs`, end to end through the client:
  - `an_integrity_check_reports_the_entire_data_set_with_rbe_when_nothing_changed`: the check waits its interval, the report carries every
    member named (RBE), and the check repeats.
  - `a_buffered_object_change_is_reported_once_with_its_last_value_after_the_buffer_time`: two changes within the buffer time give one
    report, after the buffer time, with the last value.
  - `a_report_within_its_tle_is_sent`: a report sent within its TLE reaches the client.
- Full gate green. The server tests passed twice in a row (20 of 20), so the timings are stable.

## Found on the way

- The server reads the real clock, so these tests wait for seconds (about 2 s for the integrity check, about 1 s for the buffer). They are
  the slowest tests of the file, and their bounds are loose on purpose.
- The report of an integrity check with RBE names its members (a list of variables). Without RBE it names the data set. Both are checked by
  the existing tests and by C5.

## Not done, and why

- **The critical acknowledgement is not tested end to end, and is not implemented end to end.** The client has no acknowledgement method, and
  its `ReceivedReport` carries no critical flag, so a caller cannot acknowledge a critical report. The server does not receive an
  acknowledgement either (its module documentation says so). The link tests the rule (`a_critical_report_is_acknowledged_by_its_sequence_number`,
  `a_critical_report_not_acknowledged_in_time_is_a_data_failure`), but the path through MMS is missing. This is the gap recorded as D-046 and
  D-049; it stays open for C6 (client) and C7 (server), and is to be stated in the matrix (C8).
- **A report that is too late is discarded end to end.** The link discards it (`a_report_that_would_take_longer_than_its_tle_is_discarded`),
  but on a loopback connection no report takes longer than a TLE of seconds, so the server test cannot provoke it. The bench would need a
  delay in the network; recorded as a gap for C8.
- **RBE with the buffer and the integrity check together** is not tested end to end; the link covers the combinations.
