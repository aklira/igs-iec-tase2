# B3 — Data values and data sets

## Prompt

Run task B3 of `IMPLEMENTATION.md`: the reads and writes of the data values, the creation and deletion of the data sets, and
their errors, from IEC 60870-6-503 §6.6, §6.7 and §7. Done when there are tests per operation.

## Summary

- **Data values**: `crates/igs-iec-tase2-link/src/data.rs`: `get_data_values` and `set_data_values` (per item), and
  `get_data_value_type`. The values are kept by the caller behind the `Store` trait, which reports the existence of an
  object, its write errors and its type (D-033).
- **Data sets**: `Vcc` holds the data sets with their members. `create_data_set` and `delete_data_sets` check in the order of
  the standard (D-035, D-036); `get_data_set_element_values` and `set_data_set_element_values` answer per member, and refuse
  the special identifiers (D-034). A list of values of another length is refused (D-037).
- **Table**: `BilateralTable::with_data_set_creation` grants the Create Data Set permission, which no object's list holds
  (D-035).
- **Errors**: `ErrorCode` with its `ErrorClass` (access, definition, resource), as the standard gives it.
- **Decisions**: D-033 to D-037.
- **Tests**: `tests/data.rs`, 26 tests: each operation, its success and each of its errors.
- **Dependencies**: `igs-iec-tase2-link` depends on `igs-iso9506-mms-codec` for `Data` and `TypeDescription`.
- **Gate**: `cargo fmt --all --check`, clippy with `-D warnings`, the workspace tests (163 passed), `cargo deny check` and
  `codegen --check`, all green.

## Found on the way

- A write of an invisible or unreadable member of a data set was first answered `OBJECT-NON-EXISTENT`, because the element
  operation reused the data value read. The standard answers `OBJECT-ACCESS-DENIED` for a member (§7.2.4.4.3), so the
  element operations now check the member themselves.
- The create checks refused every member with the visibility answer; the standard answers access denied for any refusal of
  a member (§7.2.4.2.3). The mapping is now the standard's.

## Not done

- The Get Data Set Element Names (§7.2.4.7) and the Get Data Value Names and Get Data Set Names (GetNameList) are not in B3:
  they are name lists over the same objects, and belong with the server's services (S1).
- The active transfer sets that reference a data set are supplied by the caller; B4 gives them.

## Reading

IEC 60870-6-503 §7.2.3 (the data value operations: Get, Set, Type), §7.2.4.1 to §7.2.4.5 (the data set operations: Create,
Delete, Get and Set Element Values), §7.2.4.2.3 (the special identifiers). No standard text is in the code or the documents.
