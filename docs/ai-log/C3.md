# C3 — Information messages (link)

## Prompt

Run task C3 of `IMPLEMENTATION.md`: the information message transfer set and the information message, in the link, sans I/O, with
the operations of IEC 60870-6-503 that block 4 names.

## Summary

- `crates/igs-iec-tase2-link/src/information.rs`: `InformationMessage` (the references and the stream, with the header of 6-802 §6.4),
  `from_parts` (the first `Size` octets of a received buffer), `buffer_name` and the padded buffer, `InformationReport` (the two named
  variables in the order of 503 §7.2.5.5.4), and `InformationTransferSet` (Start Transfer, Stop Transfer, report while ENABLED, numbered
  from 1).
- Tests: 13 unit tests and 2 property tests in `crates/igs-iec-tase2-link/tests/information.rs`. `proptest` is a dev-dependency of the
  link (MIT or Apache-2.0, as the model's).
- Decisions: D-061 (the server reports, the trigger is local; the table A.10 status is `i` with the block superscript, read on the
  page image), D-062 (the buffer sizes).

## Found on the way

- The standard gives no list of buffer sizes (6-802 §6.4 gives examples only). The list is a local choice, recorded as D-062.
- The information messages can be sent by either role in 6-503 §5.3.9.1, but the MMS mapping gives them only from the server (§6.8).
  The mapping is followed; the gap is recorded in D-061.

- The first reading of table A.10 was wrong (`I4` read as mandatory). The page image shows `i` with a superscript: corrected in D-061.
