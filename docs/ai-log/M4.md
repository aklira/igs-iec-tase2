# M4 — Transfer sets, conditions, data set types

## Prompt

Run task M4 of `IMPLEMENTATION.md`: the transfer sets (DSTransferSet, TSTransferSet, TATransferSet, IMTransferSet), their
conditions and the supported features, from IEC 60870-6-503 §6.9 to §6.14 and §8.2. Done when each type round-trips and
the bit positions are checked against the generated tables. A missing brace in the published TSTransferSet must not
change its components.

## Summary

- **Boolean enumerations**: the enumerations whose base is Boolean (block data, critical, RBE, all changes reported,
  status) are now MMS Booleans, `bool` newtypes with the names as constants. They were integers, so a Boolean value
  from a peer was refused (D-020).
- **Reserved bits**: a bit named `reserved` has no constant or accessor; the generator had kept one of them, under a
  name that covered one bit of eight (D-021).
- **Main text prevails**: the names defined in the main text and in an annex are exported at the root of the file, so
  `iso503::TSTransferSet` is the main text's definition; the annex copies stay in their clause modules (D-022, D-003).
- **Copies of the transfer sets**: the main text and the two annexes describe the same components of TSTransferSet
  and TATransferSet. The data's brace anomaly (pages 95, 150, 154) does not change them: the copies were compared
  component by component, and each copy round-trips in the tests.
- **Tests**: `tests/transfer.rs` (11 tests): the Boolean enumerations and their refusals, the status, a DSTransferSet
  round trip with the order of its components, the scopes of the object name, the three copies of TSTransferSet, the
  copies of TATransferSet and IMTransferSet, the bit positions of DSConditions, TSConditions, TAConditions and
  SupportedFeatures (every value round-trips), and the root names.
- **Decisions**: D-003 (test recorded), D-020, D-021, D-022.
- **Gate**: `cargo fmt --all --check`, clippy with `-D warnings`, the workspace tests, `cargo deny check`, and
  `codegen --check`, all green.

## Found on the way

- The generator's enumeration path did not know the base of an enumeration: the data gives `base: Boolean` on the
  inline type, which the generator ignored. The base is now read.
- The generated `SupportedFeatures` had a `RESERVED` constant for bit 2 only, while bits 5 to 9 are reserved too.
- Annex G's `TSConditions` names bit 3 `MaiMMSPDU` where the main text says `MaxMMSPDU`: the bit is the same, the name
  is the annex's (the annex is informative, D-003).
- The main text's `SupportedFeatures` says that `Block1` always has the value 1: the type keeps the value received
  (D-021).
