# I2 — The data operations of the interop with the third-party peer

## Prompt

Add the data operations to the interop with the third-party peer, in both directions.

## Summary

- `igs-iec-tase2`: `Client::names_in_domain` lists the named variables or the data sets of the client's domain with GetNameList, every
  page of the list. `igstase2-client names [--data-sets]` prints them. The peer's server answers it; our server does not serve it.
- The forward tests (our client against the peer's server) list the peer's objects at run time, so no name of the peer is written in
  the repository. They check that every listed variable is answered, that a data set of two variables is created, read, and deleted, that
  a write the peer does not permit is answered with an error, and that the data sets are listed.
- The forward tests run with the peer's domain and table identifier from the environment, as the earlier ones do: seven interop tests
  pass in one run with the peer's example server and our reference peer.

## Reverse direction (the peer's example client against our server)

- The maintainer authorised reading the peer's example sources. The example client uses a VMD-specific device, a VMD-specific
  point, a data set of its domain, and a transfer-set step. Its command is OPEN (0), and CLOSE is 1 (the public header). Its
  names are only in the bench's configuration, which is git-ignored.
- To hold them, the server's configuration may name VMD-specific objects with the empty domain, and an access may name its own
  domain (`igstase2-server`, documented in igstase2-server.md).
- A real defect was found and fixed: the two bits of a tag were read and written swapped. CLOSE-ONLY-INHIBIT (2) is the string `1 0`.
  Our client and our server agreed on the swapped order, so the bench's own tests had not seen it (CHANGELOG, Fixed).
- The reverse data test: its tag, its command, the read of the VMD point, and the read of the data set pass.

## Not done

- The transfer-set step of the example client (the next transfer-set name and the attributes of that transfer set) is not served
  by our server. It is the one known gap of the reverse data operations.
- GetNameList is not tested against our server, which does not serve it; its pagination (`more_follows`) is only checked by reading
  the code.
