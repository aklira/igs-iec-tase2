# S2 — `igstase2-server`: the demonstration server and the bench device

## Prompt

Run task S2 of `IMPLEMENTATION.md`: a `igstase2-server` binary with points from a TOML file and simulated changes. Done when
it is documented and usable as the bench's device under test.

## Summary

- **Binary**: `crates/igstase2-server/` (`src/main.rs`, `src/config.rs`, `src/simulate.rs`). Options: `--listen`, `--config`,
  `--max-associations`, `--help`. It serves the points, data sets, transfer sets and Bilateral Tables of its file, and makes
  the simulated changes at their periods. Ctrl-C stops it (status 0); a bad file exits with status 2 and names the object.
- **Configuration**: TOML, strict (unknown keys refused), every reference checked (D-052). Documented in `docs/igstase2-server.md`
  with the example `bench/device/tase2-demo.toml`.
- **Simulations**: ramp, toggle and sine, computed by `simulate::Stepper` without a clock, and tested.
- **Bench**: `bench/device/build-tase2.sh` builds the binary in the bookworm image; compose service `device-tase2`; the probe
  `crates/igs-iec-tase2/examples/probe.rs` reads the device and receives its reports (D-053). The run was made on the bench's
  container: it associates, reads, and receives three transfer reports.
- **Library**: `igs_iec_tase2::Error` implements `Display` and `std::error::Error`, so that a binary and the probe can use `?`.
- **Decisions**: D-052, D-053.
- **Tests**: `igstase2-server`: 15 unit tests (the configuration refusals, the valid file, the simulations) and 3 process
  tests (the help, the refusal of a bad file with its status, a client of the table that reads a value the simulation changes).
- **Gate**: the TASE.2 workspace: `cargo fmt --all --check`, clippy with `-D warnings`, the tests (232 passed), `cargo deny check`
  and `codegen --check`, all green; the server also builds with Rust 1.85.

## Found on the way

- The configuration's refusal of a simulated read-only point was needed: the first design sent the simulation's changes to a
  point the store refuses, so the transfer reports would have carried values the store does not hold.
- A TOML value of a real may be an integer (`value = 5` for a float): the configuration accepts it and converts it.
- The probe found no fault in the server; the reports of the bench show the simulated values as expected.

## Not done

- The interop matrix and the load test against the device (S3, which needs the reference peer for TASE.2).
- The T2 client binary, which will replace the probe as the bench's client.

## Reading

IEC 60870-6-503 §5.2.3, §5.3.4 (the access control and the Bilateral Table), §7.2.2 (the association), §7.2.5 (the transfer sets
and their reports). The MMS device of the bench (`docs/igsmms-server.md` in the sibling repository) for the file's format. No
standard text is in the code or the documents.
